# A-SPICE 4.1 CL2 산출물 감사 스킬

이 스킬은 Automotive SPICE(A-SPICE) PAM(Process Assessment Model) 4.1과 ISO/IEC 33020 능력수준(Capability Level) 모델을 기준으로, 특정 프로세스의 산출물(Work Product)이 **Capability Level 2(CL2)** 를 만족하는지 점검하는 방법을 규정한다.

## 1. CL2의 의미

CL2는 CL1(프로세스 수행, PA1.1)이 이미 달성된 상태에서 아래 두 프로세스 속성(Process Attribute)이 추가로 충족되어야 한다.

- **PA2.1 성과 관리(Performance Management)**
- **PA2.2 산출물 관리(Work Product Management)**

이 스킬은 특히 **PA2.2(산출물 관리)** 를 중심으로 산출물 자체를 점검하되, 산출물에서 확인 가능한 범위 내에서 **PA2.1**의 흔적(계획, 모니터링, 책임/자원 배정 근거)도 함께 확인한다.

## 2. Generic Practice(GP) 체크리스트

### PA2.1 성과 관리
| GP | 내용 | 산출물에서 확인할 근거 |
|---|---|---|
| GP2.1.1 | 프로세스 수행 목표 정의 | 계획서/품질목표 문서에 정량/정성 목표 명시 |
| GP2.1.2 | 프로세스 수행 계획 및 모니터링 | 일정/마일스톤 계획, 진척 리뷰 기록 |
| GP2.1.3 | 프로세스 수행 조정(계획 대비 이탈 시 조치) | 이슈/리스크 로그, 변경 이력, 재계획 근거 |
| GP2.1.4 | 책임과 권한 정의·할당·전달 | 역할(RACI), 승인자/작성자 서명 |
| GP2.1.5 | 필요한 자원과 정보 식별·제공 | 도구/템플릿/참조자료 목록, 교육 기록 |
| GP2.1.6 | 이해관계자 간 인터페이스 관리 | 리뷰 참석자, 배포 목록, 커뮤니케이션 기록 |

### PA2.2 산출물 관리
| GP | 내용 | 산출물에서 확인할 근거 |
|---|---|---|
| GP2.2.1 | 산출물 요구사항(내용·구조) 정의 | 템플릿/양식 표준, 산출물 특성표(Annex) 대비 |
| GP2.2.2 | 문서화·형상관리 요구사항 정의 | 문서관리 절차, 명명규칙, 버전 규칙 |
| GP2.2.3 | 산출물의 식별·문서화·형상관리 | 문서 ID, 버전, 이력(Revision History), 저장소/베이스라인 상태 |
| GP2.2.4 | 정의된 요구사항 대비 리뷰 및 조정 | 리뷰 기록, 결함/코멘트 처리 이력, 승인 서명 |

## 3. 점검 절차

1. **범위 확정**: 점검 대상 프로세스(예: SYS.2, SWE.1~SWE.6, MAN.3, SUP.1, SUP.8, SUP.9, SUP.10 등)와 해당 산출물 목록을 사용자에게 확인하거나 저장소 구조에서 추정한다.
2. **산출물 존재 확인**: 프로세스별 기대 산출물(§4 참조표)이 실제로 존재하는지 확인한다. 누락 시 Major 결함으로 표시한다.
3. **GP2.2.1/2.2.2 확인**: 산출물이 조직 표준 템플릿/양식을 따르는지, 필수 항목(목적, 범위, 식별자, 버전, 작성/검토/승인자, 이력)이 있는지 확인한다.
4. **GP2.2.3 확인**: 문서 ID·버전·베이스라인 상태, 변경이력 관리 여부를 확인한다. 형상관리 도구/저장소에서의 상태(승인/베이스라인 vs 초안)를 구분한다.
5. **GP2.2.4 확인**: 리뷰/검토 기록(리뷰어, 일자, 발견사항, 조치결과)이 존재하는지, 결함이 해소되었는지 확인한다. 리뷰 기록이 없으면 CL2 미충족(Major)로 판단한다.
6. **PA2.1 흔적 확인**: 계획-실적 대비, 책임자 지정, 자원/인터페이스 관리 근거를 보조적으로 확인한다(산출물만으로 완전한 PA2.1 판정은 불가하므로 관찰사항으로 남긴다).
7. **트레이서빌리티 확인**: 산출물 간 추적성(예: 요구사항↔아키텍처↔테스트)이 요구되는 프로세스라면 연결 여부를 확인한다.
8. **등급 산정**: ISO/IEC 33020 척도(N/P/L/F: Not/Partially/Largely/Fully achieved)로 GP2.2.1~2.2.4 각각 평가하고, PA2.2 종합 등급을 산정한다. CL2 판정 기준은 PA2.1, PA2.2 모두 "Largely(L)" 이상이어야 한다.

## 4. 프로세스별 주요 산출물 참조표 (요약)

| 프로세스 | 주요 산출물 |
|---|---|
| MAN.3 프로젝트 관리 | 프로젝트 계획서, 일정, 리스크 목록, 진척 보고서 |
| SUP.1 품질보증 | QA 계획, QA 검토/감사 기록, 부적합 보고서 |
| SUP.8 형상관리 | 형상관리 계획, 형상항목 목록, 베이스라인 기록, 변경이력 |
| SUP.9 문제해결관리 | 문제 기록/이력, 원인분석, 조치 결과 |
| SUP.10 변경요청관리 | 변경요청 기록, 영향분석, 승인 이력 |
| SYS.2 시스템 요구사항 분석 | 시스템 요구사항 명세, 요구사항 추적 매트릭스 |
| SYS.3 시스템 아키텍처 설계 | 시스템 아키텍처 문서, 인터페이스 명세 |
| SYS.4/SYS.5 통합·검증/시스템 검증 | 통합/검증 전략, 테스트 케이스, 테스트 결과 |
| SWE.1 소프트웨어 요구사항 분석 | SW 요구사항 명세, 추적 매트릭스 |
| SWE.2 소프트웨어 아키텍처 설계 | SW 아키텍처 문서, 동적 행위 설명 |
| SWE.3 소프트웨어 상세설계 | 상세설계 문서, 단위 설계 명세 |
| SWE.4 소프트웨어 단위 검증 | 단위 테스트 전략/케이스/결과, 커버리지 리포트 |
| SWE.5 소프트웨어 통합 및 통합 테스트 | 통합 전략, 통합 테스트 케이스/결과 |
| SWE.6 소프트웨어 검증(Qualification Test) | 검증 전략, 테스트 케이스/결과, 요구사항 커버리지 |

프로젝트에 해당 산출물 경로/파일이 없으면 "산출물 미확인" 결함으로 보고하고, 사용자에게 실제 산출물 위치를 확인한다.

## 5. 결과 보고 형식

각 발견사항은 다음 항목으로 구조화하여 보고한다.

- **프로세스 / 산출물**
- **관련 GP** (예: GP2.2.3)
- **등급** (N/P/L/F)
- **관찰 근거** (파일 경로, 구체적 내용)
- **결함 심각도** (Major / Minor / Observation)
- **권고 조치**

마지막에 프로세스별 PA2.2(및 확인 가능한 PA2.1) 종합 등급과 CL2 달성 여부(Yes/No/조건부)를 요약한다.
