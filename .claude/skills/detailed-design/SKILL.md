# 상세설계(Detailed Design) 스킬

이 스킬은 ISO 26262-6:2018 clause 8(소프트웨어 유닛 설계 및 구현)과 Automotive SPICE 4.1 SWE.3(소프트웨어 상세설계)를 동시에 만족하는 상세설계를 작성·평가·문서화하기 위한 방법론을 정의한다. 상세설계는 아키텍처 설계(`architecture-design` 스킬, SWE.2)의 컴포넌트/인터페이스를 구현 가능한 수준까지 세분화하는 단계다.

## 1. 상세설계 원칙 (ISO 26262-6 clause 8 / A-SPICE SWE.3)

### 1.1 ISO 26262-6 유닛 설계 원칙 (ASIL에 따라 적용 강도 조정)
| 원칙 | 내용 |
|---|---|
| 유닛의 계층적 구조 | 아키텍처 요소를 더 이상 분해할 필요가 없는 구현 단위(함수/클래스/모듈)까지 세분화한다 |
| 제한된 유닛 크기 | 하나의 함수/유닛이 과도하게 커지지 않도록 크기·복잡도를 제한한다(§8) |
| 높은 응집도 | 하나의 함수/유닛은 하나의 명확한 처리만 수행한다(§2) |
| 낮은 결합도 | 유닛 간 결합은 파라미터/반환값(데이터 결합) 수준으로 제한한다(§2) |
| 포인터/재귀/인터럽트/동적 메모리 사용 제한 | ASIL이 높을수록 제한을 엄격히 적용하고, 사용 시 근거와 검증 방안을 명시한다 |
| 정적/동적 행위 기술 | 함수 계약(§4)과 알고리즘/상태전이(§6, §7) 모두 기술한다 |

### 1.2 A-SPICE SWE.3 Base Practice
| BP | 내용 |
|---|---|
| BP1 | 소프트웨어 상세설계 개발 — 아키텍처 요소를 구현 가능한 유닛으로 세분화하고 유닛 간 인터페이스/호출관계를 기술 |
| BP2 | 상세설계 평가 — 평가 기준(가독성, 재사용성, 시험용이성 등)을 정의하고 대안을 비교(§9 연계) |
| BP3 | 요구사항/아키텍처 요소 ↔ 상세설계 유닛 간 양방향 추적성 확립(§11 연계) |
| BP4 | 상세설계와 아키텍처/요구사항 간 일관성 보장(§5 공통 자료형 일관성 포함) |

## 2. 응집도·결합도 원칙 — 유닛 수준, **필수 준수**

- 아키텍처 수준의 응집도/결합도 원칙(`architecture-design` 스킬 §2)을 함수/클래스 수준으로 구체화한다.
- 하나의 함수는 하나의 책임만 가진다(과도한 분기/다중 목적 함수는 결함으로 표시하고 분리를 제안한다).
- 유닛 간 통신은 **파라미터·반환값·명시적으로 정의된 자료형(§5)**으로 제한한다. 전역 가변 상태 공유, 다른 유닛의 내부 필드 직접 접근은 금지한다.
- 유닛 간 호출 그래프(§3 상세 호출관계)에 순환 호출이 발견되면 결함으로 표시하고 재구성을 제안한다.

## 3. SOLID 원칙의 코드 수준 적용

| 원칙 | 상세설계 적용 방법 |
|---|---|
| SRP | 함수/클래스당 하나의 변경 이유만 갖도록 설계한다 |
| OCP | 분기 조건이 반복되는 지점은 전략(Strategy)/다형성으로 대체해 신규 케이스 추가 시 기존 코드 수정을 최소화한다 |
| LSP | 상속/구현 관계에 있는 클래스는 계약(§4 사전·사후조건)을 위반하지 않고 치환 가능해야 한다 |
| ISP | 거대 클래스/모듈 대신 역할별로 분리된 작은 인터페이스(추상 클래스/프로토콜)를 정의한다 |
| DIP | 구현 모듈은 구체 클래스가 아닌 추상(인터페이스/프로토콜)에 의존하도록 import 방향을 설계한다 |

## 4. 함수/모듈 계약 정의 규칙 (템플릿 §5) — **필수**

아키텍처 인터페이스 계약(`architecture-design` 스킬 §4)을 함수/모듈 단위로 구체화한다. 각 핵심 함수는 다음을 반드시 포함한다:
- 입력/출력(자료형, 단위, 유효 범위)
- 사전조건(Precondition)/사후조건(Postcondition)
- 부작용(Side Effect, 상태 변경·I/O 등)
- 예외/오류 반환 계약
- 시간 제약(WCET, 호출 주기, 타임아웃 — ASIL 관련 유닛은 필수)

## 5. 공통 자료형 및 데이터 무결성 규칙 (템플릿 §4)

- 공통 데이터 구조, 열거형, 단위(SI 단위 등), 유효 범위, 불변조건(Invariant), 직렬화 규칙을 한 곳에 정의하고 모든 유닛이 동일 정의를 참조하게 한다.
- 동일 개념에 대해 유닛마다 다른 자료형/단위를 재정의하면 일관성 결함(BP4)으로 보고한다.

## 6. 알고리즘·정책 결정표·상태전이 작성 규칙 (템플릿 §6, §7, §8)

- 핵심 알고리즘은 의사코드 또는 흐름도로 처리 순서, 분기 조건, 경계값을 명시한다.
- 정책/의사결정표는 입력 조건 조합이 **상호배타적이고 전체를 포괄(mutually exclusive & exhaustive)**해야 한다. 누락되거나 중복되는 조건 조합은 결함으로 보고한다.
- 상태전이 상세는 상태 저장 위치, 전이 함수, 이벤트, 가드 조건, 타이머, 초기화 동작을 포함한다.

## 7. 설계 대안 평가 절차 (SWE.3 BP2)

- 알고리즘/자료구조/모듈 분해에 **유의미한 트레이드오프가 있는 대안**이 존재하는 경우(예: 성능-메모리, 재귀-반복, 동기-비동기), 대안을 §9 평가 기준으로 비교해 제시하고 `AskUserQuestion`으로 사용자 확인을 받는다.
- 대안이 자명하거나 아키텍처 단계에서 이미 결정된 경우는 생략할 수 있으나, 생략 근거를 간단히 기록한다.
- 평가 기준: 가독성/유지보수성, 재사용성, 시험용이성(Testability), 성능/자원 사용, ASIL 관련 안전성(§8 연계).

## 8. 오류/방어적 설계 규칙 (템플릿 §10)

- 모든 유닛은 경계에서 입력을 검증한다(방어적 프로그래밍). 유효하지 않은 입력·예외·자원 실패에 대한 검출, 처리, 기록(로깅), 복구 동작을 명시한다.
- 아키텍처 수준 오류 격리 메커니즘(`architecture-design` 스킬 §1.1)을 유닛 코드 수준에서 구현하는 지점을 명확히 연결한다.

## 9. 코딩 및 검증 규칙 (템플릿 §11)

- 코딩 표준은 프로젝트 구현 언어에 맞게 적용한다.
  - Python: PEP 8 및 정적분석 도구(예: pylint, mypy, bandit) 적용, 타입 힌트 사용을 권고한다.
  - C/C++: MISRA-C/C++ 등 안전 관련 언어 서브셋과 스타일 가이드를 적용한다.
- 순환복잡도(Cyclomatic Complexity) 등 복잡도 제한 기준을 정의하고, 초과하는 유닛은 분해를 제안한다.
- 단위시험/커버리지 기준은 SWE.4(단위 검증) 산출물과 연계하며, 여기서는 상세설계 관점의 시험용이성 요구사항만 정의한다(예: 의존성 주입 가능 여부, 순수 함수화 여부).

## 10. 외부 의존성 및 구현 경계 관리 (템플릿 §13)

- 신규 외부/OSS 라이브러리를 도입하는 경우, `TPL-SBOM-001`(Python 의존성 SBOM/FOSS 라이선스 목록)에 라이브러리명, 버전, 라이선스, 적용성 검토 결과를 기록한다(SWE.3/SUP.8 연계). 라이선스 적합성이 불확실하면 임의로 승인하지 말고 사용자에게 확인한다.
- 자체 구현 범위와 생성 코드/플랫폼 종속부/외부 라이브러리로 위임하는 범위를 명확히 구분해 기록한다.

## 11. 추적성 (템플릿 §12, §14)

- 아키텍처 요소 ↔ 상세설계 유닛 ↔ 소스 파일/함수 ↔ 단위시험(SWE.4) 항목 간 양방향 추적을 유지한다.
- `architecture-design`/`requirements-engineering` 단계에서 이미 만든 추적 매트릭스가 있으면 유닛/소스 파일 컬럼을 추가해 확장한다. 없으면 새로 만들되 위치를 사용자에게 확인한다.
- 상위 링크(아키텍처 요소)나 하위 링크(단위시험)가 없는 유닛은 고아(Orphan)로 표시하고 결함으로 보고한다.

## 13. 표준 근거 요약

- **ISO 26262-6:2018 clause 8**: 소프트웨어 유닛 설계 및 구현은 유닛의 계층적 구조, 응집도·결합도 원칙, 포인터/재귀/인터럽트/동적메모리 사용 제한(ASIL 기반), 코딩 가이드라인 준수를 포함해야 한다.
- **A-SPICE 4.1 SWE.3**: 아키텍처 요소를 구현 가능한 유닛으로 세분화 → 유닛 인터페이스/호출관계 기술 → 상세설계 대안 평가 → 요구사항/아키텍처 ↔ 유닛 간 양방향 추적성 → 일관성 확보의 흐름을 따른다.
